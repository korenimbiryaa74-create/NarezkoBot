# Разработка: экспериментальная версия

**Не готово к самостоятельной круглосуточной работе.** Код интерфейса, очереди, мониторинга и конвейера собран в этой ветке, но установка, графический интерфейс, реальные аккаунты, Twitch и GPU на Windows ещё не проверены. Не считайте это готовым релизом.

Настольный интерфейс использует Tkinter, не Telegram. Состояние очереди хранится в SQLite. Когда ранее наблюдаемый эфир закончится, монитор ждёт VOD с тем же `stream_id` и стабилизации длительности. Это не гарантия завершения обработки VOD платформой. При ошибке Twitch переход в офлайн не засчитывается. VOD должен быть доступен и сохранён стримером.

Пайплайн: скачивание полного VOD в 160p → транскрипция кусками по 10 минут с кэшем → поиск реакций через существующую интеграцию браузерного ChatGPT → скачивание найденных фрагментов → удаление тишины → MP4 и TXT с транскриптом от начала готового видео. Qwen загружается установщиком для будущего сравнения, но **не используется** для поиска: качество сопоставимо с ChatGPT не доказано.

Результаты лежат в `recordings/<стример> VOD <ID>/`. Папка `_work` содержит промежуточные файлы и транскрипты. Настройки и секреты сохраняются в локальный `config.json`. Для некоторых сбоев скачивания и рендера предусмотрены ограниченные повторы, а после возможной неопределённой отправки запроса в ChatGPT задача останавливается для проверки: нельзя безопасно повторять запрос вслепую.

Проверки разработчика: `python -m unittest discover -s tests -v`. Все сетевые сервисы/модели в тестах подменены. Проведён локальный рендер искусственного видео через настоящий FFmpeg; это не проверка RTX или реального потока. Экспериментальный `INSTALL.bat` и `START.bat` ещё не проверены на Windows.


## Экспериментальная установка с Python 3.15

`INSTALL.bat` ищет **установленный 64-битный Python 3.15**, не меняя системный Python. Если уже существует `desktop/.venv` от другой версии, установщик остановится и ничего не удалит. Для обхода отсутствующих колёс ONNX Runtime для 3.15 новый конвейер использует внешний whisper.cpp b5454 с моделью Whisper large-v3-turbo вместо faster-whisper. Архив и модель проверяются по SHA-256. Qwen3-8B загружается, но для поиска не подключён.

Это неподтверждённое изменение: не было запуска установщика, модели, RTX 5060, Twitch и ChatGPT на Windows. Видеокарта может потребовать другую сборку CUDA или драйвер. Вход в ChatGPT и настройка Twitch необходимы вручную; полностью автономная работа не подтверждена.

Поиск Python: исправлена передача проверки версии из Windows PowerShell, добавлен поиск в реестре и ручное указание `python.exe`, если автоматический поиск не сработал. Автоматическая установка другого Python отключена на время поиска. Проверка на Windows всё ещё необходима.

## Проверка длины записи

Длительность найденного Twitch VOD передаётся в очередь и сравнивается со скачанным видео до распознавания. Недогруженное видео не считается готовым к анализу. Если старый сохранённый файл короче ожидаемого, он переносится в `_work` с пометкой `incomplete`, а при следующей попытке скачивается заново. Для ранее созданных заданий, у которых длительность не была сохранена, эта проверка недоступна. Проверка длительности не доказывает полноту обработки записи на стороне Twitch.

## Тест на локальном видео

Поместите исходники в `test_input` и нажмите «Запустить тест из папки». Локальные задания сохраняются в той же очереди SQLite, а файлы не копируются и не удаляются. Мониторинг и скачивание Twitch пропускаются; используются настоящие Whisper, ChatGPT и рендер. Для короткого теста уменьшите минимальную длину реакции. Поддерживаются MP4, MKV, MOV, WEBM, M4V и AVI, только в корне папки. При изменении или удалении исходника после постановки задание останавливается; дождитесь копирования до запуска. Повторное нажатие не дублирует активные задачи, но после завершения создаёт новый тест. Для восстановления очереди без создания новых заданий предусмотрена кнопка «Продолжить очередь».

Автоматический тест этого режима генерирует видео и проверяет результат с настоящими FFmpeg/ffprobe, но Whisper и ChatGPT подменены; это не тест Windows, GPU или реальных сервисов.

## Профили ChatGPT и лимит загрузок

Рядом с кнопкой «Войти в ChatGPT» выберите `acc_01` … `acc_07` и отдельно войдите в каждый нужный аккаунт; дождитесь события «вход выполнен». Профили и cookies хранятся в `gpt_accounts` локально, не публикуйте их. Остановите очередь перед настройкой. Если найдено явное сообщение о лимите загрузки и запрос ещё не мог быть отправлен, приложение пробует следующий существующий профиль. Неавторизованный профиль пропускается с сообщением; при неопределённой доставке, ошибке сети или блокировке безопасности переключения и повтора нет. Если все доступные профили ограничены, задача останавливается: дождитесь сброса лимита либо войдите в другой профиль и вручную повторите задание. Вход без подключения аккаунтов за пользователя не выполняется; отдельные аккаунты могут иметь собственные ограничения, соблюдайте условия сервиса. Это экспериментальная автоматизация веб-интерфейса: обнаружение лимита и переключение требуют проверки на реальном ChatGPT и Windows.

## Диагностика

В «Последних событиях» можно выделять текст, использовать Ctrl+C или контекстное меню; кнопка копирует все доступные события. Пока текст выделен, видимый журнал не перерисовывается; снимите выделение, чтобы увидеть новые события. Для полной причины ошибки выберите задание и нажмите «Скопировать ошибку выбранного задания»: подробности сохраняются в очереди и после перезапуска. Перед отправкой текста вручную убедитесь, что в нём нет ключей, cookies, паролей или адресов прокси с паролями.

Распознавание по умолчанию использует Groq Whisper Large V3 Turbo, если указан API-ключ. В настройках → «Распознавание речи» введите ключ или импортируйте только `timecodes.groq_api_key` из локального старого JSON, затем сохраните настройки. Аудио отправляется в Groq: учитывайте приватность, лимиты и возможную оплату. Прокси для Groq включается отдельно. При сетевой ошибке или отказе Groq оставшиеся части обрабатываются локальным whisper.cpp; при некорректном ответе локально обрабатывается только эта часть, а следующая снова отправляется в Groq. После трёх некорректных ответов подряд используется локальный движок до конца задания; без ключа используется локальная модель. Успешные части кэшируются, некорректный ответ не сохраняется. Тайм-аут облачного запроса не повторяется автоматически: он мог быть принят и тарифицирован. Ключи находятся в `config.json` открытым текстом — не публикуйте этот файл и не отправляйте его вместе с логами. Локальный резерв и CUDA на Windows/RTX 5060, а также реальный Groq необходимо проверить; лог ошибки загрузки модели не доказывает единственную причину сбоя.

### Whisper и Groq: диагностика

whisper.cpp запускается с относительным путём к модели и рабочей папкой whisper-cli, чтобы не передавать кириллицу в параметре `-m`. Исправление не проверено на Windows/RTX 5060. Если модель всё ещё не загружается, попробуйте путь проекта целиком латиницей и проверьте установку. HTTP 403 означает отказ в доступе, а не обязательно плохой ключ. Из ответов Groq показываются только известные коды блокировки модели проектом или организацией; остальные подробности намеренно не выводятся во избежание утечки секретов.

При неверных таймкодах локального whisper.cpp часть повторно распознаётся двумя половинами, результаты которых кэшируются отдельно. У последнего сегмента части допускается превышение конечного времени до 30,5 секунд: конец ограничивается границей, а текст помечается как требующий проверки. Предупреждение сохраняется в кэше и выводится в логе и TXT соответствующей нарезки. Другие серьёзно повреждённые таймкоды не принимаются. Если половина тоже ошибочна, работа останавливается и показывает номер сегмента и числовые границы без текста.

### Готовый ответ ChatGPT, если автоматическое чтение не сработало

Приложение получает ответ через DOM браузера, а не через буфер обмена. При текстовом запросе оно не ждёт и не скачивает случайные изображения страницы; статус ожидания виден в событиях, после пяти минут без текста и признаков генерации задача остановится без повторной отправки. Если ответ уже готов в браузере, скопируйте его полностью, закройте приложение с подтверждением прерывания, обновите код и запустите снова. На вкладке «Состояние» выберите именно нужное прерванное задание со статусом «Ошибка» и нажмите «Вставить ответ ChatGPT», подтвердив соответствие ответа заданию. Затем нажмите «Повторить выбранное задание с ошибкой» и «Продолжить очередь». Приложение проверяет синтаксис и интервалы и использует сохранённый ответ без нового запроса; окончательная проверка границ выполняется на этапе поиска. Ответ хранится локально в state и привязан к конкретному заданию. Не нажимайте «Запустить тест из папки»: это создаст другое задание. Реальная веб-страница ChatGPT может измениться; автоматическое чтение и оконный интерфейс требуют проверки на Windows.


## Ручной блюр по стримерам

В «Настройки → Обработка» включите «Размывать области по профилю стримера». Кнопка «Настроить блюр стримера…» запрашивает логин Twitch, находит последнюю доступную запись VOD, скачивает небольшой фрагмент в 160p и открывает кадр. Мышью можно выделить до 16 прямоугольников; «Убрать последнее» удаляет последнюю область, «Сохранить области» сохраняет профиль. Для стримера без баннеров можно выбрать «Без блюра» в редакторе или отдельной кнопкой без загрузки VOD. Если VOD недоступен, можно выбрать локальное видео и время кадра. Для поиска кадра Client ID/Secret не нужны: используется открытый веб-интерфейс Twitch, который может измениться. Для отдельного автоматического мониторинга эфиров Twitch по-прежнему нужны Client ID/Secret. Для кадра необходимы FFmpeg и TwitchDownloaderCLI; прокси Twitch API используется по настройке, загрузка видео — напрямую.

Профили сохраняются локально в `state/blur_profiles/<ник>.json` и применяются только к соответствующему нику (без учёта регистра). Для локального теста укажите этот ник в поле «Ник стримера для тестового видео». При включённом блюре отсутствие профиля останавливает задание до обработки, а не выдаёт незаблюренное видео. Существующие образцы в `banners/` не удаляются, но больше не используются в новом режиме.

Это фиксированные области: блюр действует всё время, даже когда баннера нет. Если баннер переедет или поменяется компоновка/соотношение сторон, профиль нужно скорректировать. Результат необходимо проверять. Для каждой нарезки формируется `— баннеры.txt` с исходными временами и координатами. Готовые видео не перезаписываются при смене настроек. Twitch, интерфейс и рендер на Windows требуют реальной проверки.

## Мониторинг и уведомления

При сохранении ручного профиля (в том числе «Без блюра») стример добавляется в список мониторинга. Уже существующие профили добавляются в список один раз при первом запуске новой версии; ранее введённые имена сохраняются. Список можно редактировать в «Настройки → Twitch и прокси». Удаление имени из списка не удаляет профиль; если снова сохранить профиль, имя добавится обратно. Сохраните Twitch Client ID и Secret и нажмите «Сохранить и запустить». Глобальный переключатель блюра должен быть включён, если области нужно применять.

Вкладка «Уведомления» показывает сохранённые события: обнаружен эфир, эфир закончился, VOD найден, обработка завершена или остановилась, и проблемы подключения. Кнопка очистки не удаляет очередь, профили или результаты. Журнал технических событий остаётся отдельно. Если ожидаемый VOD не найден 6 часов, появится уведомление; ожидание продолжается. Эфир определяется при успешной проверке, а не обязательно в момент его фактического начала.

Мониторинг и обработка работают только пока приложение запущено, компьютер не спит и есть сеть. По желанию включите «Автозапуск Windows» в настройках: он действует после входа текущего пользователя Windows и не препятствует переходу компьютера в сон. Если мониторинг ранее был включён, он возобновится при запуске приложения. После перемещения папки приложения заново включите автозапуск. Эфир, целиком прошедший при выключенном приложении, может быть пропущен. Требуются сохранённый доступный VOD и рабочие Twitch и ChatGPT. Ошибки или неопределённая отправка ChatGPT могут потребовать действий пользователя. На Windows и в реальном круглосуточном режиме эта версия ещё не проверена.

## Экспериментальная загрузка YouTube

Пошаговая настройка отдельных каналов стримеров и тестового канала, расписание, ограничения и действия при прерывании описаны в [YOUTUBE_WIP.md](YOUTUBE_WIP.md). Интеграция выключена по умолчанию и пока не проверена с реальным YouTube на Windows.

### Кэш донатов и публикация

Ответ ChatGPT о донатах уже кэшируется в `gpt_uploads/response_cache` по запросу, транскрипту и границам реакций. При повторе с теми же данными ответ берётся из кэша, а интервалы снова проверяются; изменение данных или границ приводит к новому запросу. В событиях повтор теперь отдельно отмечается как кэш ответа о донатах.

Генерация названий ChatGPT временно отключена, чтобы проверять загрузку на YouTube: новые видео получают название по имени готового файла. Дополнительного запроса ChatGPT для названия нет. Уже поставленные в очередь видео сохраняют ранее записанные названия. Код для будущей доработки названий пока не вызывается.

Для FFmpeg фильтр блюра рассчитывает радиус по фактическому размеру обрезанных цветовых плоскостей; это исправление проверено локально на коротком синтетическом кадре, но не на Windows с исходным видео пользователя. Контролируйте итоговый блюр перед публикацией.

### Проверка YouTube ещё продолжается

После нажатия публикации приложение ожидает подтверждённую ссылку на видео. Если Studio показывает распознанное окно «проверка видео ещё продолжается», по запросу пользователя приложение один раз подтверждает публикацию до окончания проверки. Это может привести к ограничениям или предупреждению со стороны YouTube. Другие окна не подтверждаются автоматически; неоднозначная кнопка или отсутствие подтверждения требуют проверки Studio до повтора. В логах отображаются этапы ожидания. Локальные браузерные тесты не заменяют реальную проверку интерфейса YouTube на Windows.

Радиусы блюра ограничены строго меньшим значением половины размера фактических плоскостей; это учитывает FFmpeg, который отклоняет радиус, равный указанной границе. Проверяйте итоговый блюр до публикации.
